# PiOpt

PI-Desktop 的控制台插件：一个插件，四个功能。

| 功能 | 做什么 |
|---|---|
| **外观** | 一处调窗口长什么样：界面动效（动画优化，强度与速度两把滑杆挂在它下面）与窗口材质（磨砂玻璃开关带模糊强度、背景图带填充方式与最近使用的缩略图网格）。依赖某个开关的选项是那个开关的二级内容，开关关掉就收起。 |
| **行为** | 聊天框里的模型浮窗：总是列出全部模型（限高仍是宿主的），搜索框下面一条「默认 / 供应商 / 厂商 / 名称」切换排列方式（面板里同一组排列方式也是一个四选一）：默认按宿主自己的顺序平铺（一行不重排，不含「最近使用」这一类），其余三种的分组与组内都按 A–Z。另有三个开关：选中行的那枚对勾换成一圈圆角边框、推理强度滑杆的档位译成中文、窗口入口搬进侧边栏（右侧面板开关的图标一并摆正）。 |
| **插件市场** | 读取已装插件与官方 catalog，经 jsDelivr / raw / GitHub Blobs API 下载更新包，按 `sizeBytes` 与 `sha256` 逐位校验后再交给你在 Plugins 页安装。 |
| **远程** | 同一 Wi-Fi 下的手机、平板或另一台电脑配对后可以看会话、发指令、停止正在运行的一轮；面板里只有一个开关、一个访问地址和一个六位配对码。 |

四者都在同一个面板里，按左侧菜单的顺序「外观 / 行为 / 插件市场 / 远程」排列并切换；命令也可以直接打开某个视图，或直接落在外观的某一节。

## 插件市场

- **更新**：列出已装插件与 catalog 里最新非撤回版本，显示体积、发布时间、更新说明。
- **准备**：按 `jsDelivr → raw → GitHub Blobs API → 官方地址` 依次尝试，每个候选 3 次重试 + 指数退避。
- **校验**：边下载边算 sha256，只有 `sizeBytes` 与 `shasum` 与 catalog 一致才从 `.part` 改名为正式文件。
- **诊断**：对指定版本逐个通道取前 1 KB，报告 HTTP 状态、content-type、体积、耗时与错误码。
- **详情**：版本卡、主页、仓库/提交/构建者、安全说明、按风险分级的权限说明、完整版本列表与 changelog。
- **可安装**：列出 catalog 里本机尚未安装的插件，同样可以准备包。
- **队列**：下载进度、阶段、来源、失败时每个通道的原始错误。

下载位置：

```
data/local.piopt/downloads/<id>-<version>.piplug
```

失败码：`SERVER_HTML`、`LINK_RESET`、`MIRROR_404`、`RATE_LIMIT`、`TIMEOUT`、`DNS`、`HTTP_ERROR`、`INTEGRITY`、`TOO_LARGE`、`CANCELLED`、`NO_SOURCE`、`WRITE_FAILED`。

## 界面动效（外观 · 第一节）

| 场景 | 默认值 | 行为 |
|---|---:|---|
| 按压 (`instant`) | 85ms | 按钮下移 1px，释放即时对称回弹 |
| 控件与轻浮层 (`fast`) | 135ms | hover、focus、开关、分段器、箭头旋转、菜单与气泡弹出退回 |
| 内容与折叠 (`base`) | 195ms | 页面/标签页进入、消息与卡片、内联展开收缩、侧栏往返伸缩 |
| 空间弹层 (`slow`) | 260ms | Dialog、全局搜索、侧滑抽屉 Sheet 与工作面板往返伸缩 |
| 空间幅度 | 2 / 4 / 7 / 10 / 16 px | 微浮层 / 折叠与卡片 / 消息与对话框 / 面板 / 抽屉 |
| 弹层缩放 | 0.988 / 0.982 → 1 | 轻浮层 / 模态层建立层级，不弹跳 |

整套动画使用**统一的对称减速度语言**（`--pm-ease-symmetric` + 宿主 `--motion-*` 全量桥接）：

- **全场景覆盖**：除主题 CSS 外，桥接宿主自身的 `--motion-duration-*`、`--motion-ease-*` 与 `--default-transition-duration`，覆盖控件、开关、分段器、17 类折叠箭头、`<details>` 原生折叠、侧栏与工作面板联动、路由与标签页切换、聊天流消息/思考/工具/子代理/评审卡片、Composer 芯片与排队提示、菜单/Popover/Tooltip/Dialog/Sheet 及 Toast 通知。
- **可往返动画双向对称、随时可打断**：展开↔收缩、弹出↔退回共享同一时长（`exitRatio = 1`）与同一曲线。对留在树上的状态切换使用 CSS `transition` 与 `details::details-content`；对宿主 React 直接卸载的折叠块与浮层，以及半途反向的侧栏/工作面板，由宿主窗口内的 `renderer/motion-runtime.mjs` 在不触碰 React 真实节点的前提下用惰性克隆与三次贝塞尔瞬时进度采样完成对称退回与半空反向接力。

入场关键帧统一用 `animation-fill-mode: backwards`，**不用 `both`**：`both` 会保留最终帧，而最终帧里的 `transform` 会永久留在元素上，让宿主的 `position: fixed` 浮层（右键菜单、侧栏二级菜单）改以它为参照。同理，可能挂载子菜单的 `[role="menu"]` / 右键菜单只做透明度过渡、不做位移；菜单项（`[role="menuitem"]`）也不参与“按下去 1px”。

同时，**任何包裹着磨砂表面的容器都不动画 `opacity`**：`opacity < 1` 的元素在 CSS Filter Effects 2 中同样是 Backdrop Root，动画播放期间它里面的 `backdrop-filter` 看不到后面的背景图。因此 `.app-shell` 与 `.main-pane` 都不挂入场动画，改成动画它们里面的内容层（`.chat-surface`、`.route-page`、`.settings-content` 等）；工作面板与侧栏的进出场（含 `sidebar-in-pm` / `sidebar-out-pm` 与 `work-panel-in-pm` / `work-panel-out-pm`）只做位移和宽度伸缩、不改 `opacity`，且关键帧名保留宿主 `onAnimationEnd` 依赖的前缀。

两个开关：

- **完全禁用动画**：把所有过渡与动画压到 1ms。用 1ms 而不是 `none`——宿主靠 `animationend` 卸载进场节点，`none` 会让这些事件永远不来。
- **动画优化**：关掉后完全不写动效规则（协调器同步旁路），界面就是 PI-Desktop 自己的行为。

层级照依赖关系排：**运动强度、响应速度、跟随系统减弱动态是「动画优化」的二级内容**——它们只改这一层写出去的动效规则，父项关掉就没有意义，于是整块收起（缩进成一枚内嵌的浅槽，`grid-template-rows` 0fr/1fr 过渡；收起时 `inert`，键盘与读屏都跳过看不见的控件，父项开关上带 `aria-expanded`）。「完全禁用动画」是同级开关而不是二级项：它优先于总开关（开着时即使「动画优化」关了也写 1ms 规则），必须随时可达。它开着时**「动画优化」这一层整体不可用**——父开关连同三个二级项一起禁用，标题、滑杆与开关自己变灰，不另加说明文字；关掉它即恢复。「外观基底」不受这两个开关影响，仍是一级行。
- **推理强度滑杆的吸附**：这一层开着时，聊天框里那条推理强度滑杆落到哪一格就「吸」到哪一格——滑钮与进度条走一条带过冲的曲线（先越过一点再回落），点亮的那一格同时弹一下。**拖动中也一样**：宿主在拖动态把过渡关成 `none`，这里用更具体的选择器把它压回来，滑钮每一格都是「吸」过去的（`--pm-fast`，比松手后的 `--pm-base` 更快，才能跟得上指针）；`reduced` 预设与系统「减弱动态」都不做这层过冲。

速度滑杆只影响时长；强度滑杆只影响位移与缩放，范围 **0.40–2.00×** 与 **50–150%**（5% 一档，1.00× 位于速度滑杆 37.5% 处）。拖动滑杆或切换明暗基底后**自动生效**：面板先即时更新读数与自身动效令牌，再在 80ms 防抖后写入并应用宿主主题。连续拖动只提交最后一版参数，同步进行中的新改动会补发。
明暗底色交叉淡变是**例外**：它固定 1.00×（160ms），不随速度与强度伸缩——换色属于系统级变化，跟着调慢只会让整个窗口显得迟钝。
状态点与标题栏显示「正在同步 / 实时应用已就绪 / 实时同步失败」。失败时参数保留在本地，调整任一选项即可重试。

插件只写**一个**运行时主题 `PiOpt Appearance`（动效与玻璃层都在里面），它的基底由上面那三档决定：

- **自动**：跟随系统外观（浅/深），面板打开或点它时读取系统真实值；
- **浅色 / 深色**：固定使用该基底，不再看系统。

“自动”要读系统的真实深浅。宿主会把 `nativeTheme.themeSource` 设成当前主题的基底，于是面板里的 `prefers-color-scheme` 只是在回显我们自己写进去的值。所以系统值改由插件进程直接读：Windows 查注册表 `AppsUseLightTheme`，macOS 读 `AppleInterfaceStyle`，Linux 读 `gsettings` 的 `color-scheme`。这只是一次几毫秒的读取，不动当前主题，因此打开面板不会再整窗换色闪一下。只有三种方式都读不到时（无 shell、未知桌面），才退回旧做法：把主题短暂交还宿主（`system`）、读一次、再接管回来——那一步会闪，所以只是兜底。拖滑杆不会重复测量。

同一时刻宿主里只会出现这一个 `PiOpt Appearance` 主题，旧版本注册的 `Motion Lab · Light` / `Motion Lab · Dark` 会被自动移除。它只含动效规则与（可选的）玻璃层，不覆盖任何 `--ds-*` 颜色 token。动效和材质共用这一个主题，所以下面「窗口材质」一节说的玻璃层也写在它里面——改动其中任何一边都会重建整张样式表，不会只剩一半。

## 窗口材质（外观 · 第二节）

给界面加一层磨砂玻璃：侧栏与标题栏改用半透明底色并模糊其后内容，菜单、对话框与弹出层用更强的模糊。开关和两档参数都在面板里，改完即时生效。开关只管"表面是否磨砂"，底图与内容区透视独立于它——关掉开关照片照样在，只是不再模糊。

层级也照依赖关系排：**模糊强度是「启用磨砂玻璃」的二级内容；「填充方式」与「最近使用」是「背景图」的二级内容，而且这一段常开**——没有图片时它仍然要能点「不使用」和最近使用，否则整段收起就再也选不回来了。磨砂开关关掉时只有模糊强度收起（值原样留着，重新开回来还是原来那档）。

| 参数 | 默认 | 说明 |
|---|---|---|
| 启用 | 关 | 只控制表面是否模糊；关掉时背景图仍然显示，表面保持清晰 |
| 模糊强度 | 100% | 60–160%，放大模糊与光场；底色随强度略微变厚，保证小字仍有底 |
| 背景图 | 无 | 选一张图片做玻璃背后的底；没有图时用柔光场。与开关无关，关着玻璃也照样显示。显示上传时的源文件名，不显示路径 |
| 填充 | 拉伸填满 | 拉伸填满 / 等比适应 / 等比铺满 / 原始尺寸 |

「最近使用」保留最近 8 张背景图，是背景图这一节的缩略图网格：最前面固定一个「不使用」的块（斜线方块），点它就清掉当前背景图、回到无图状态——所以面板上不再有单独的「清除」按钮。后面每张一张 1:1 圆角卡片，名字在图片下方，点卡片就切到那张图（当前这张有一圈强调色）；鼠标悬停或键盘焦点进入卡片时，右上角才出现删除图标，点了先弹确认（正在使用的那张会提示删除后回到无背景图），确认后才从列表移除并清掉数据目录里的副本。

卡片里的缩略图由面板自己画：上传时从文件直接缩一张 96px 的中心方图 PNG，随条目存进设置。升级前已有的图片没有这一份，面板会逐张向主进程要一次原图字节（`wallpaperBytes`）现画一次再存回（`saveThumb`）。插件主入口跑在独立的 Node 进程里，没有 Electron 的 `nativeImage`；面板又读不到插件数据目录（宿主的 fs 范围只覆盖工作区），所以缩略图只能这样产生。画不出来时卡片只剩文件名，不影响应用与删除。

| 质感 | 模糊 | 弹层模糊 | 侧栏底色 | 标题栏底色 | 弹层底色 | 光场 | 有图时内容区 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 轻薄 | 16px | 22px | 72% | 58% | 76% | 16% | 62% |
| 标准 | 28px | 38px | 82% | 66% | 82% | 22% | 74% |
| 厚重 | 44px | 59px | 90% | 74% | 88% | 28% | 86% |

侧栏底色（`--pg-sidebar-alpha`）**刻意高于内容区**（`--pg-canvas-alpha`）。宿主自己给侧栏的是整块界面里最深的那个色（暗色 `--ds-bg-under` = `#000`，主框体 `--ds-bg-primary` = `#181818`），它只有在基本遮住背后的图时才仍然比主框体深。alpha 给低了，浅色照片会把侧栏冲亮到主框体亮度的两倍（实测 63–65 对 34–35），看上去像"侧栏才是浅的那个"。所以侧栏读的是 `--ds-bg-under`，且 alpha 高于内容区。

四条规则各自解决一个问题：

1. `.app-shell::before` 铺背景层：有背景图时就是那张图，没有时是一层柔光场。宿主界面底色是一整块纯色，半透明表面盖上去只能看到同一个颜色，`backdrop-filter` 也没有东西可模糊。`z-index:-1` 让它落在 `.app-shell` 自己背景之上、内容之下，不改动任何层级。
2. 侧栏（`.sidebar-surface` / `.sidebar-rail`）、右侧工作面板（`.work-panel`，玻璃画在它的 `::before` 上，原因见下）都用半透明底色加模糊：它们各自铺的是宿主的 `--ds-bg-under` / `--ds-bg-dock`，换成同色但带 alpha 的混色后，背后的图或光场就透出来了。侧栏额外复用宿主写给 macOS 的两支 sheen 变量（`--ds-sidebar-glass-sheen-top` / `-bottom`）做顶部高光。

   横幅材质由变量 `chromeFill` 统一下发，窗口标题栏 `.main-titlebar`、会话顶部条 `.conversation-topbar`、右上角装最小化 / 最大化 / 关闭的 `.window-controls`、工作面板表头 `.work-panel-header` 拼进**同一个选择器**——不是四份拷贝，拷贝就是它们跑偏的方式。`.window-controls` 要归进来，是因为宿主给它的是 `position: fixed` 的实色块（`background: var(--ds-bg-primary)`），并且在**打开工作面板时会换成 `--ds-bg-dock-raised`**——于是那个角上永远是一块和旁边标题栏不同的材质。

   但 `chromeFill` 只是这套材质的一半，另一半是它**底下垫着什么**。会话顶部条是主内容区的子元素，它的模糊是「透过内容区那层底色」去取样的；工作面板表头如果只叠 `chromeFill`、底下直接是原图，就会又暗又艳，看上去像透明而不是磨砂。所以面板的玻璃层 `.work-panel::before` 用一条渐变分成两段：顶部 `--ds-toolbar-height` 这一段铺的正是内容区那层底色（`--pg-canvas-alpha`），往下才换成面板自己的 `--ds-bg-dock`。表头再叠 `chromeFill`，它的模糊取样到的底与顶部条完全一致——实测表头带 `235,243,255`、顶部条 `234,242,254`。同一条 46px 里只叠这一份玻璃，不会出现表头与标题栏之间的"双层"色差。

   这层画在 `.work-panel::before` 而不是 `.work-panel` 上：带了 `backdrop-filter` 的元素是 Backdrop Root，它后代的 `backdrop-filter` 只能取样到这个祖先内部，看不到更底下的背景图。伪元素在绘制顺序上与内容是兄弟关系，不会拦截取样。

   材质层还必须**独立于动效开关**抑制宿主的 `.work-panel` 进出场动画。宿主的 `work-panel-in` 使用 `both` 且关键帧含 `opacity`；即使动画被压到 1ms，保留的 opacity 效果仍会让 `.work-panel` 成为 Backdrop Root，导致色差在静止时也一直存在。这正是动效总开关关闭或完全禁用后问题复发的原因：此前只有开启动效时的覆盖规则顺带挡住了它。现在材质层始终写入 `animation: none` 和不透明度不变的 `work-panel-out-glass` 退场保护；开启动效时再由动效层的 `pm-panel-right-in` 接管滑入。


   模糊在"界面家具"与浮层上是安全的：宿主的浮层（右键菜单、二级菜单、通知、用量气泡等）都渲染在组件内部、用 `position: fixed` 加视口坐标，不是这些表面的后代，所以给侧栏、标题栏、工作面板、输入框磨砂都不会把弹层重新锚定。
3. 内容区（`.main-pane`）只改底色不透明度，不加滤镜——它里面有 composer 等固定层，加 `backdrop-filter` 会改变它们的包含块。没有背景图时这一项是 100%，等于不改。
4. 菜单、对话框与弹出层用更强的模糊（`--pg-blur-strong`，轻薄 22px / 标准 38px / 厚重 59px），聊天输入框用与侧栏同一档的 `--pg-blur`：它们本来就浮在活动内容之上，模糊在做实事而不是装饰颜色；输入框是这一层里唯一的大面积表面，半径再大只是白烧 GPU。浮层分两种画法（原因见下文"弹层与输入框"）：一层浮层把滤镜放在元素自己身上，可能打开二级菜单的那一层与聊天输入框把磨砂画在 `::before` 上。

### 背景图

选一张图片做玻璃背后的底。图片**不是**内联进 CSS 的：

1. 面板用 `<input type="file">` 读出字节。渲染进程拿不到文件路径（Electron 已移除 `File.path`），所以按 base64 交给插件进程。
2. 插件把它写进自己的数据目录：`~/.pi-desktop/plugins/data/local.piopt/wallpaper.<ext>`，同一时间只保留一张。
3. 主题 CSS 里写的是**绝对路径** `url("C:/…/wallpaper.png")`。宿主在 `themes.upsert` 时校验扩展名与 4 MB 上限，再把它重写成 `plugin-asset://…` 注入窗口。

这样 256 KB 的主题 CSS 预算完全不受图片大小影响，图片上限就是宿主自己的 4 MB 资源上限。

| 界面上的名字 | 内部值 | CSS | 行为 |
|---|---|---|---|
| 拉伸填满 | `fill` | `background-size:100% 100%` | 铺满整个窗口，比例会变形 |
| 等比适应 | `contain` | `contain` + 居中 | 整张图完整显示 |
| 等比铺满 | `cover` | `cover` + 居中 | 铺满窗口，超出部分裁切 |
| 原始尺寸 | `none` | `auto` + 居中 | 按图片原始像素显示，超出裁切 |
| 等比不放大 | `scale-down` | 限宽高的盒子 + `contain` | 缩小到放得下，但不放大 |


`scale-down` 是唯一 CSS 表达不了的：`background-size` 读不到图片的自然尺寸。所以插件读图时顺手从文件头解析宽高（PNG 的 IHDR、JPEG 的 SOF、WebP 的 VP8/VP8L/VP8X、SVG 的 `width` 或 `viewBox`），把 `::before` 的盒子压到 `min(100%, 自然尺寸)` 再用 `inset` + `margin: auto` 居中（不用 `transform`），最后由 `contain` 填满这个盒子——等价于 `object-fit: scale-down`。读不到尺寸时（AVIF）退回 `contain`：会放大，但不会错位。

图片上还压着一层 `--pg-scrim`（轻薄 12% / 标准 20% / 厚重 28%）。压暗做在背景图层里，而不是靠表面的 `background-color`：实测同一次渲染里，侧栏上半段叠上了底色、下半段没有——`background-color` 与 `backdrop-filter` 的合成顺序在分块边界上并不稳定。把压暗放进图层之后，不管哪个表面透出来，看到的都是同一个亮度。

背景图的显示与开关**无关**。开关只决定表面是否磨砂（`backdrop-filter` 与半透明底色），底图、内容区透视与表面不透明度由"有没有图"决定：无图且关掉玻璃时生成器直接返回空字符串，界面与原来逐像素一致。所以关掉玻璃时，照片仍铺在整个窗口底下，内容区仍是半透明的，只是表面不模糊了。用 400×300 的测试图在 1828×1216 的窗口里实测（玻璃关闭）：

- `fill`：窗口左边缘就是图片的蓝色；
- `scale-down`：左右各留约 104px 露出光场，图片居中。

图片被删除或移动后，插件在加载时和每次 `glass.getState` 都会发现，并清掉这个引用——留着它会让 `themes.upsert` 直接失败，连带动效层一起掉。

### 平台限制：插件不能让窗口透出桌面

PI-Desktop 在 Windows 11 上以**不透明窗口**运行，插件改不了这一点：

- 宿主创建窗口时用 `transparent: false` 换取 DWM 原生圆角，而 `transparent` 是 `BrowserWindow` 的构造参数，建好之后无法更改。`setBackgroundColor` 在非透明窗口上忽略 alpha，宿主还额外用 `toOpaqueElectronBackgroundColor` 把 alpha 混掉。
- 窗口上的 `DWMWA_SYSTEMBACKDROP_TYPE` 其实已经是 `2`（Mica），`WS_EX_NOREDIRECTIONBITMAP` 也已设置——Mica 层一直都在，只是被 Chromium 的不透明合成层整个遮住。
- 实测（0.21.0 / Windows 11 26H2，build 26300）：用 `renderer.extension` 把 `html`、`body`、`#root`、`.app-shell`、`.main-pane`、`.sidebar-surface` 全部改成透明，侧栏的纯黑确实消失，但露出来的是 Chromium 不透明根层的默认深色 `#121212`，不是桌面壁纸。

所以这一节做的是**窗口内的磨砂分层**：玻璃背后是上面那层柔光场，不是桌面或其它窗口。要真正透出桌面只能改宿主、把窗口建成透明窗口，那已经超出插件边界，而且每次升级 PI-Desktop 都要重打。

### 为什么玻璃和动效在同一个功能里

`pi.themes.upsert` 是插件往宿主窗口注入样式的唯一通道（`renderer.extension` 只能改自己挂的那几个节点，不能当样式表用）。所以玻璃规则和动效规则本来就写在**同一张**样式表里，由 `features/appearance/index.js` 的 `applyTheme` 拼接 `features/appearance/motion.js` 与 `features/appearance/glass.js` 的输出：

```js
const css = `${motion.buildThemeCss(motionLayer, base)}${glassLayer}`;
```

这也是两者合成了一个功能、而不是两个功能互相调用的原因：任何一边改动都走同一个 `applyTheme`，样式表永远带着两半，不会出现「调了材质结果动效丢了」这种半张表的状态。旧版本用 `glass.bindTheme` 把 `motion.refreshTheme` 接进玻璃功能，那层回调在合并后已经去掉。

这意味着**玻璃需要 PI-Desktop 选中 `PiOpt Appearance` 主题**才生效；切到别的主题时玻璃一并消失，但开关状态存在插件设置里，切回来就恢复。

玻璃层只用 `--pg-*` 变量，不重定义任何 `--ds-*` 颜色 token，也不使用 `transform`——`transform` 与 `backdrop-filter` 都会让元素成为 `position: fixed` 后代的包含块。这条约束由 `test/glass.test.js` 守住，且只检查**属性声明**、不检查注释：注释里讨论 `transform` 是正常的事，不该让散文触发一条关于行为的规则（测试会先剥掉 `/* … */` 再匹配 `transform:`）。

这条规矩背后是实测踩过的坑。宿主**把二级菜单嵌在父菜单内部**（`.sidebar-submenu` 是 `.sidebar-floating-menu` 的子元素），两级的坐标都由 JS 从 `getBoundingClientRect` / `innerWidth` / `innerHeight` 算出来，是**视口坐标**。所以只要给父菜单本身加了 `backdrop-filter`，子菜单的 `top`/`left` 就不再相对视口，而是相对父菜单——表现为二级菜单“被关在上一级窗口里出不来”。

侧栏、标题栏、`.work-panel::before` 与输入框上的模糊是安全的：它们的 `position: fixed` 后代里没有靠视口坐标定位的宿主菜单（浮层嵌在父菜单里，而父菜单本身不带滤镜，见下一节）。

### 弹层与输入框

聊天输入框（`.composer-shell`）、模型选择器、右键菜单，以及输入框里每个按钮弹出的浮窗都上磨砂，分两种画法：

| 画法 | 用在 | 为什么 |
|---|---|---|
| 滤镜直接在元素上 | 不再打开任何浮层的“一层”弹窗：`.composer-model-menu`（含推理强度浮窗）、`.composer-autocomplete`、`.sidebar-submenu`、用量气泡、设置里的各类选择菜单 | 它自己就是滚动容器，只有把模糊放在元素上，列表滚动时磨砂才跟着走 |
| 磨砂画在 `::before` 上 | 可能打开二级菜单的那一层（`.context-menu`、`.sidebar-row-menu`、`.composer-permission-menu`、`.composer-mode-menu`、`.agent-capability-menu` 等）与聊天输入框 | 伪元素不是任何节点的祖先，不会成为二级菜单的包含块；输入框里嵌着模型 / 权限 / 思考这些浮窗，直接加滤镜会把它们的视口坐标变成相对输入框的坐标 |

两种画法的观感是同一份材质：弹层读 `--pg-blur-strong`、输入框读 `--pg-blur`，sat 都是 `--pg-saturate`，填充都是 `--pg-overlay-alpha` 的半透明底。弹窗的底色与模糊顺序也不会歪：伪元素叠在元素底色之上，而底色是均匀色，`blur(α·底色 ⊕ 背后)` 与 `α·底色 over blur(背后)` 是同一个结果。

输入框是这一层里唯一被重画底色的宿主表面：它原本是不透明的 `--ds-bg-composer`（暗色主题下是 `--ds-bg-elevated-primary`），现在换成同色的 `--pg-overlay-alpha` 混色，背后才有东西可透；不支持 `backdrop-filter` 的环境退回宿主自己的实色。模型选择器原先在暗色主题下由宿主自带一层 40px 模糊，现在统一由这一层接管（`--pg-blur-strong`），浅色主题同样生效。

## 行为：模型选择器

聊天框里的模型浮窗默认只列最近使用的三个模型，其余收在「其他模型」后面。行为这一层把它改成：

- **总是列出全部模型**：打开浮窗时替宿主点一次「其他模型」，随后把入口藏掉，用户不能再把它收回去。浮窗的限高仍由宿主自己决定（`.composer-model-menu` 的 `max-height`、`.composer-model-list` 的 280px 滚动），这一层没有动过任何一个高度。
- **排列方式**：搜索框下面单独一条「默认 / 供应商 / 厂商 / 名称」，点哪个是哪个（不占搜索框的位置，输入框拿回整行宽度）。面板的行为视图里是同一组四选一（写同一个值），所以两处永远读到同一个排列方式。
- **按默认**：设置里排的那份顺序，一个平铺列表 —— 不分组、也不按名字重排：「最近使用」那一类连标题一起没有，那几行回到它们在各自供应商组里的原位；没有分组抬头写着供应商，所以每行下面补一行淡色的来源。
- **按供应商**：一条服务一组；最近使用过的模型回到各自那一组（宿主展开时它们被单独放在最上面）。供应商名称那行平时不压底色；吸顶到列表顶部时，只在文字外面罩一枚圆角小块 —— 近乎实色的底、一层模糊和一点投影，像压在列表上的一片浮层，滚过去的模型行不会和标题叠在一起，也不会拉一条整行的色带。
- **按厂商**：按模型厂商分组（`claude` → Anthropic、`glm` → Zhipu AI、混元 → Tencent…），认不出的模型落在它的供应商名下。分组名与组内模型都按 A–Z：拉丁字母在前、中文在后。
- **按名称**：全部模型平铺，同样按 A–Z；每个选项下面另起一行居左的淡色小字写着来源。
- **品牌图标**：每个模型前面一枚 14px 的彩色品牌标（lobe-icons，随包内置、不联网）。Claude 系（`claude`/`sonnet`/`opus`/`haiku`）用自家那朵橙色菊花而不是 Anthropic 的 A 标，混元用那颗蓝球（供应商写「腾讯混元」也认）。匹配先看模型名与 id（`claude`、`gpt`、`glm`、`gemini`…），再看供应商名 —— OpenRouter、Azure 这类转售商下面跑的仍显示模型自家的标。两个都认不出时画供应商首字母的彩块，所以没上表的新模型、新服务也不会空着。加品牌只需在 `tools/build-model-icons.js` 的表里加一行，再重新生成 `renderer/model-logos/icons.mjs`。
- **选中标记**：默认是宿主那枚对勾；打开「圆角框替代对勾」后对勾藏起来，改用一圈 2px 的内描边把选中的模型整行框住（圆角沿用宿主给选中行的那一档），行高、内边距与滚动位置都不动 —— 克隆行与宿主原生行（搜索时）一起生效。
- **中文推理强度**：宿主把档位原名直接写在滑杆的刻度上，也写在发送键左边那枚思考 chip 上（`off` / `omit` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`；`omit` 是「不发送这个参数、由模型自己决定」）。打开这一项后它们换成「关闭 / 默认 / 极低 / 低 / 中 / 高 / 极高 / 最高」，`title` 与 range 的 `aria-valuetext` 一起换，读屏念的也是同一条；原名写回 `data-piopt-mp-level`，宿主重渲染后还能认出是哪一档。滑杆里那排装饰圆点不动（它们是 `aria-hidden` 的圆点，塞汉字只会从圆点里挤出来）。
  - **不闪英文**：滑杆那块的变化在浮窗自己的 `MutationObserver` 里**同步**译完（回调早于绘制），而且整批扫完才决定要不要重建 —— 半路 `return` 会把同一批里跟在别的改动后面的滑杆记录丢掉，拖动时就会漏成英文。chip 的观察者盯的是**整枚 chip**（不是那枚 span）：React 换档时可能把 span 整个换掉，盯 span 会盯到一个已经不在文档里的节点，之后就不再有任何回调。菜单一挂上 `data-piopt-mp-levels="zh"`，还没写回原文的刻度先 `visibility:hidden`（那排本来就是 `aria-hidden` 的装饰），所以不会先画半帧英文。从面板切回来、窗口重新获得焦点时会再补看一眼 chip，不必等下一次开浮窗。
- **最近使用那几行的能力标记与位置**：宿主只在这组里写来源，推理/视觉徽标和上下文读数只画在供应商分组里，而且它把这几行从分组里剔了出去。这一层用宿主的另一次渲染把这些问出来 —— 搜索时它不过滤最近使用、又会用供应商名匹配整组，所以先按模型 id 搜出徽标与上下文，再按供应商名逐组搜一遍拿回设置里的完整顺序；前者按「供应商␟模型 id」缓存进 `piopt.modelPicker.capabilities.v1`，后者整份缓存进 `piopt.modelPicker.order.v1`（模型增删或换序时自动重探）。宿主不响应程序化搜索时立刻放弃、不影响浮窗。

设置存在插件 settings 的 `modelPicker` 键里，整份只有三个字段：`grouping`、`frameSelected`、`translateThinking`。宿主窗口的 `renderer/model-picker.mjs` 每次打开浮窗都经 `plugin.call` 读一次，按钮点击则立刻写回去，改完不用重启。窗口入口那个开关另存一份（`navEntries` 键），见下一节。

实现上不碰宿主的 React 节点：

1. 点一次宿主自己的折叠入口。`display:none` 的按钮仍然可以被 `.click()` 触发，所以入口一出现就点开、随后由样式藏起来。
2. 原生列表整体让位，用 `cloneNode(true)` 出原生按钮自建一份视图（按默认原序平铺、按供应商分组、按厂商分组或按名称平铺）。克隆时摘掉最近使用行右侧那枚来源（改由名称下面那行淡字承担）、去掉键盘高亮的瞬时类，并给选中行补上宿主只给分组行挂的 `active` 与 `composer-model-check`（最近使用组的选中行原本两样都没有，上下文读数与对勾不会跟着变白）；点克隆行只是转交给对应的原生按钮，选中模型仍走宿主自己的逻辑。

不搬动原生节点是有原因的：宿主在搜索、方向键高亮、模型异步加载时都会重渲染这棵子树，被搬走的节点会让它下一次 `insertBefore` 找不到参照。搜索框一有输入，自建视图整体让位，显示宿主自己筛出来的结果。


## 行为：窗口入口

宿主把「新建任务」「搜索」放在会话标题栏右上角，把「收起侧边栏」放在侧边栏头部。打开「调整功能入口」后这两件事一起改：

- **侧边栏展开**：两个入口搬进侧边栏头部，摆在「收起侧边栏」左边，顺序是新建任务、搜索、收起。
- **侧边栏收起**：它们跟着「切换侧边栏」排到它的右边，顺序是切换、新建任务、搜索。非聊天页那一枚在标题栏左侧（`.titlebar-nav` 里），位置关系相同。会话标题同步向右让位：宿主只给一个按钮留了 `padding-left:calc(var(--ct-lead-inset) + 36px)`，这里再补上两个入口的宽度（`+ 2 * 32px`），标题不会被压住。
- **原位不再有入口**：会话标题栏右上角那一对（连同标题栏里宿主自己的「新建任务」）用**内联** `display:none !important` 隐去 —— 是搬家，不是复制。用内联样式而不是属性 + 样式表，是因为宿主重绘会换掉节点、属性跟着没了，按钮就会在藏与露之间闪。点注入的按钮就是点宿主原来那一枚：新建任务仍走宿主自己的命令，搜索仍打开宿主自己的搜索框；原按钮不在这一页时才退回宿主的 ⌘/Ctrl+K 合成按键。
- **右侧面板开关的图标摆正**：`.app-work-panel-toggle` 那枚图标在自己的方框里偏右下。这一层量两个盒子的中心差（`offset` 系列，不吃 `transform` 的影响），用 `--piopt-panel-icon-shift-x` / `-y` 把它平移回正中；一像素以内不动，宿主本来就在正中时什么都不设。

设置存在插件 settings 的 `navEntries` 键里（`enabled` 一个布尔值），面板写、`renderer/nav-entries.mjs` 读；窗口重新获得焦点或重新可见时补看一眼，所以从面板切回来即时生效。

实现上仍然不搬宿主的节点：注入的两个按钮是自己的（`data-piopt-nav-action`，样式 `piopt-nav-action` 沿用标题栏那一档 28px 与 `--radius-md`），位置随侧边栏状态在 `.sidebar-header-actions` 与 `.ct-lead`（或标题栏的 `.titlebar-nav`）之间挪；锚点找不到时先摘下来，等下一次扫描再放回去。宿主重绘会换掉它自己的节点（也可能带走注入的按钮），`MutationObserver` 每批 mutation 在一个 microtask 里同步复位 —— 不留几十毫秒的去抖窗口，那一小段真空期正是「闪一下才回来」的来源。控制台里 `__pioptNavEntries.inspect()` 能读出当前的锚点、两个入口挂在哪、藏了几个原按钮、以及图标的平移量，排查时先看它。
## 远程（局域网控制）

同一 Wi-Fi 下的手机、平板或另一台电脑可以看这台电脑上的会话、发指令、停止正在运行的一轮。面板里只有三样东西：一个开关、一个访问地址、一个六位配对码。

- **开会话**：面板里打开「开启远程访问」，端口默认 8790（可改，1024–65535，改端口会重启一次网关）。地址不止一个时优先显示 `192.168.*`、`10.*`、`172.16–31.*` 这类内网地址，其余地址列在下面那行。
- **配对**：设备连同一个 Wi-Fi，扫面板上的二维码（或手输地址），输入六位配对码（`换一个` 可随时换）。二维码由 `renderer/qr.js` 本地生成，不上传、不联网。配对成功后这台设备拿到一个设备令牌，存在浏览器本地，之后不再输入；面板的「已配对设备」里可以移除某台设备。
- **新建会话**：列表右上角的「＋」列出这台电脑上的项目（按最近打开排）和第一项「临时聊天」；选中即在那个项目里建会话，或者建一个不绑定项目的会话，然后直接进去发指令。项目是按文件夹认的，所以「临时聊天」就是不传路径的同一次调用，不是另一种会话类型。
- **远程能做什么**：列出全部会话，按项目文件夹折叠（没有项目的归到「临时会话」，每组都能折叠，折叠状态记在这台设备上）、读一个会话最近的 80 条消息、发一条指令、中止正在运行的一轮。详情页每 3 秒刷新，会话列表另有一条 SSE 推送，桌面这边跑完的一轮不用在设备上点刷新。会话列表与元数据走桌面通道 `session/list`、`session/get`；插件自己的 `session.*` 只对「插件创建的会话」开放（`session.read.own`），不是这里要的数据。对话正文取自该会话自己的 jsonl，只读末尾 256 KB 并按文件大小缓存。长按（桌面浏览器右键）自己的某条消息，可以「从这里重新问」：宿主分叉到这条之前，新会话带着当时的项目与原样历史，这条的内容回到输入框里等你改完再发；原会话一个字都不动。正在运行的会话不能分叉（宿主拒绝），会提示等这一轮结束。对话按块渲染：思考过程收在「思考」里可展开，每次工具调用单独一行（工具名、目标、耗时，点开看参数与结果），正文用 Markdown 渲染；只有用户消息是气泡，agent 的正文直接铺满页面，和宿主窗口一致；时间只打在每轮结束的那条回复末尾（当天只写时分，跨天补日期，工具行不重复写，它自己带耗时）；正在跑的一轮在对话末尾显示「正在处理 12s」，会话列表里对应的那一行同时亮着运行中的灯。对话从文件开头读起，因此长会话也一定带出最初那个问题，中间跳过的条数在顶部写一次（如「省略了 641 条更早的消息」）；读取是增量的，有新消息时只解析新增的几行。
- **电脑浏览器里也一样**：这一页不是只给手机用的。窗口窄时列表、对话、配对轮流占满一屏；宽度过 900px 后左边固定 316px 的会话列表、右边是对话，选中的那条在列表里保持高亮，顶栏的刷新与「＋」两个按钮也留在对话页上，新建会话的底部弹层改成屏幕中央的对话框。对话正文自己滚动（不再由整页承担），所以「停在最新一条」是在真正滚动的元素上量到的；宽窗口里正文的阅读宽度被限制在一行读得过来的长度。悬停态、细滚动条这类桌面才有的反馈只在指得动的设备上出现。
- **停在提问上的一轮会标出来**：会话列表给正在等回答的会话挂「等你回答」，点进去在输入框上方显示它在等什么（Agent 的提问、待确认的工具权限、待批的计划），以及提问给的选项。
- **能看见，不能替点**：`agent/askTool/resolve`、`tool/resolvePermission`、`plans/resolve` 在宿主里都是 `dangerous`，插件发起的调用一定要回到屏幕上确认一次，所以回答仍要在这台电脑上点；远程这边只能告诉你它在等什么，别让对话看起来还在跑。删除、改名、切换项目也不开放。
- **安全**：网关只在开关打开时监听 `0.0.0.0`，除页面本身外每个请求都要设备令牌；配对接口按来源地址限速（一分钟五次）；`Origin` 只接受这台机器自己的地址，别的网页拿着令牌也打不进来。关掉开关或卸载插件，端口立即释放。设备令牌存在插件数据目录的 `remote-devices.json`（临时文件加改名，原子写），不放在插件设置里——开发态每次保存都会重启插件，放在设置里的数组会被整块覆盖，已经配对的设备就会被踢回配对页。

- **重载不掉线**：开发态热重载会重启插件进程，网关按 `remoteAutostart` 记住开关状态并自行恢复，页面重连即可，配对不受影响。

## 侧边栏入口

PI-Desktop 左下角那排按钮里，PiOpt 的入口排在第二个（插件）之后：

- 图标就是面板标题栏里 PiOpt 名字左边那三根竖条（6 / 13 / 9 px，3px 柱、2px 间距），用当前图标的颜色画，所以静止时和相邻四个一样灰、悬停一起变亮；命中区仍是宿主的 32×32 `.footer-action`，悬停显示「PiOpt 控制台」。
- 点一下打开 PiOpt 面板，停在上次看到的视图（命令 `PiOpt: 打开控制台` 才会固定切到市场）。
- 宿主没有给这个位置提供插槽，所以入口由 `renderer/entry.mjs` 直接挂在宿主窗口里：定位 `.sidebar-footer .footer-actions`，插到 `[data-nav="plugins"]` 之后，宿主重新渲染把它冲掉时自动补回，插件卸载时移除。
- 宿主要是改了底部按钮栏的结构、找不到那个锚点，入口退回放在这一排的末尾而不消失。
- 面板自己声明 `pi-plugin-chrome: v3`（paint-through）：顶部 46px 仍归宿主，由它按可交互元素切成拖拽段，并且**不再插那行「开发提示 · 顶部 46px 为拖拽区」**——v2 面板才会显示。

## 安装与使用

要求 PI-Desktop **0.21.0 或更高**（`manifest.engines` 据此声明）：面板的 `pi-plugin-chrome: v3` 与左下角入口都依赖这一代宿主。
打包时校验器会给出两类提示，都不代表功能缺失：

- `permission.high-risk`：`renderer.extension`、`net.fetch`、`agent.tool.register`、`agent.prompt.inject` 需要在安装时由你明确授权，这是设计如此。
- `permission.unused`：校验器只扫描 `main.js`，而实际调用位于 `features/market/index.js`（`net.fetch`、`clipboard.writeText`、`agent.registerTool`）。权限声明与真实调用一致。
1. 在 PI-Desktop 的 Plugins 页安装 `dist/local.piopt-1.0.0.piplug`。
2. 命令面板运行 **PiOpt: 打开控制台**，或直接运行功能命令：

| 命令 | 效果 |
|---|---|
| `PiOpt: 打开控制台` | 打开面板，进入插件市场 |
| `PiMarke: 准备全部可用更新` → `Pimarket: 准备全部可用更新` | 打开面板并串行准备所有可用更新 |
| `PiOpt: 打开外观` | 打开面板，进入外观视图（界面动效一节） |
| `PiOpt: 打开窗口材质` | 打开面板，进入外观视图并滚到窗口材质一节 |
| `PiOpt: 打开远程访问` | 打开面板，进入远程视图 |

面板左侧菜单最上方有一个展开/收起按钮：收起时只显示图标，展开后菜单加宽并写出「外观」「行为」「插件市场」「远程」四个名字，选择记在面板本地，下次打开保持。菜单里点一下或 `Alt+1` / `Alt+2` / `Alt+3` / `Alt+4` 都能切换视图（编号就是菜单顺序）。外观视图里「界面动效」与「窗口材质」是同一页的两节，命令打开时会自动滚到对应那一节。
切换时选中指示条在两项之间滑过去（160ms），新视图淡入并从下方 4px 归位；系统开启「减少动态效果」时两者都关掉。

## 权限与边界

声明：`ui.panel`、`renderer.extension`、`ui.theme`、`clipboard.write`、`net.fetch`、`shell.openExternal`、`agent.tool.register`、`agent.prompt.inject`、`desktop.control`、`session.read`。

| `Pimarket: 准备全部可用更新` | 打开面板并串行准备所有可用更新 |

- 只写自己的数据目录：`~/.pi-desktop/plugins/data/local.piopt/`（市场可在设置里改）。
- 市场功能不安装、不卸载、不启用/禁用、不改 `registry.json`、不启动任何进程。
- 下载只允许 `https`，主机硬编码为 `cdn.jsdelivr.net`、`raw.githubusercontent.com`、`api.github.com`、`plugins.aiuo.net`，每一次重定向都按同一白名单复核；单包上限 50 MB。
- 内置文件是 HTML 的响应按 `SERVER_HTML` 丢弃，绝不当作包。
- 外观（动效 + 材质）只注册一个运行时主题：CSS 里只有动效规则与玻璃层（背景填充、渐变、`backdrop-filter`），不含颜色 token，除自己数据目录里那张用户选的背景图外不访问文件与网络；`ui.theme` 只用于这一个 `PiOpt Appearance` 主题（基底随设定切换）。
- `agent.prompt.inject` 只用于收录 `skills/piopt.md`（按需加载），不会自动往消息里注入内容。
- `renderer.extension` 只用于一个渲染模块：在宿主窗口左下角的按钮栏里挂一个入口按钮，点击经 `plugin.call` 交回插件进程打开面板；不读文件、不访问网络、不改动其他插件的界面，卸载时移除自己挂的东西。
- 远程功能只在开关打开时占用一个局域网端口，服务的是插件自己的远程页面与四类接口（列会话、读一个会话、发指令、中止）；数据全部经 `pi.session.*` 与 `pi.desktop.invoke` 的 `agent/prompt`、`agent/abort` 取用，审批类（`dangerous`）操作一律不开放，设备令牌保存在插件设置里，关闭开关或卸载时端口立即释放。

### 主题互斥

PI-Desktop 一次只能选择一个主题，外观层不能叠加在另一个第三方主题上。调整外观（动效或材质）会切换到匹配的宿主 Light/Dark 基底再附加动效与玻璃规则，原先选中的第三方主题不会继续生效。

工作面板、浏览器等原生 `WebContentsView` 有独立渲染进程，主题 CSS 无法跨文档控制其内部动画。

## 开发（免打包热重载）

改代码不需要 `.piplug`。PI-Desktop 的 **Plugins → Load development plugin** 会直接从目录加载并监听改动：

1. 在 Plugins 页点 **Load development plugin**，选择本目录 `E:\AgentProjects\PiOpt`。
2. 之后保存任何文件，宿主自动重载插件，不需要重新打包、也不需要重新安装。
3. 只有 `manifest.json` 的 `permissions`（或 `manifest.fs` 范围）变化时才需要显式重新加载一次——这是宿主的授权设计，不是缓存问题。

注意：

- 开发期间请**禁用**已安装的 `local.pimarket` 与 `local.pi-modify`。PiOpt 复用了 `pimarket.open`、`pi-modify.open` 等命令 id，同时启用会出现重复命令，插件列表里也会多出一套旧的外观主题。
- 入口按钮用的是 `renderer.extension`：它是权限项，宿主在授权变化后不会热更新，所以首次加载或改动权限后要重新加载一次插件（必要时重启）按钮才会出现。
- 纯界面迭代可以先用浏览器打开 `renderer/index.html` 看布局：没有宿主 bridge 时会自动进入独立预览模式。

校验与测试：

```bash
node --test test/*.test.js
node --check main.js
```

只有要发布或交给别人安装时才打包，且必须由 PI-Desktop 的 `PluginPack` 生成（`.piplug` 是 store-only zip，不能用普通 zip/tar 代替）。
